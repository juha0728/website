A wellness app that teaches, and never diagnoses.

Vitality lets people enter their habits and goals, then returns educational suggestions on food, movement and medication basics. They can save what helps. This page follows the project from a written brief to a working prototype.

Stage 1 · The question

How do you personalize health guidance without giving medical advice?

The brief set one hard limit before any screen existed. Recommendations are educational. The app does not diagnose diseases, and it never tells anyone to start, stop or change a medication. Every later decision had to respect that line.

Stage 3 · User flow

One path from sign-in to a saved resource

Logged-out visitors go to login or sign-up. Everyone lands on the dashboard, fills in a health profile, picks a category, and gets recommendations they can save. Two loops matter most: refine and try again when the results miss, and the medication safety branch.

Stage 5 · Build

A working prototype in one React file

The brief and the visual direction came from me. The code was generated and revised in conversation with Claude, Anthropic's AI assistant, then extended one request at a time. The result is a single file of about 1,700 lines. Accounts and data live in the browser's storage, so it runs with no server.

How recommendations are chosen

No black box. Each item carries tags, the saved profile produces a set of tags, and items that match more tags rank higher. "Refine search" changes the goal tags and runs it again.

// condensed from the app
const profileTags = new Set([
  profile.activityLevel, profile.sleepHabits,
  profile.eatingHabits, ...profile.goals
]);
const scored = pool.map(r => ({
  r, score: r.tags.filter(t => profileTags.has(t)).length
}));
scored.sort((a, b) => b.score - a.score);

Stage 6 · Safety by design

The medication concern flow

The rule shown on the landing page, profile form and medication page

This platform provides general educational health and wellness information only. It is not a substitute for professional medical advice, diagnosis, or treatment.

  • No diagnosis of any condition.
  • No instruction to start, stop or change a medication or dose.
  • Allergies, conditions and medications are optional, never required.
  • Anyone who reports a side effect gets general safety information and a push toward a pharmacist or prescriber.

Stage 7 · Iterations

What changed, and what is next

  1. v1

    Full prototype from the brief

    Landing, auth, dashboard, check-in, profile form, three recommendation categories, saved resources, history, settings and the medication safety flow.

    Shipped
  2. v2

    Guest mode

    Reviewers should be able to explore without signing up. Guest mode opens with a sample profile, six days of check-in history and a few saved items. Today's check-in is left empty so the flow can be tried. A banner explains that guest data stays on the device.

    Shipped
  3. v3

    Guided flows for the three main buttons

    Diet: choose ingredients you have, such as eggs, then see menus using them with photos, steps and a recipe.

    Exercise: choose home, gym or outside, then a category (cardio, full body, plyometric, upper body, lower body, flexibility, abs). Each shows a suggested number of sets and rest time.

    Medication: start with "why do you want medication?", pick the body area (headache, stomach, muscle, bone, back), then see general over-the-counter information from public sources, with side effects written in red.

  4. Later

    Statistics page

Known limits

  • Sign-in is a prototype. Passwords are stored in plain text in the browser, so it needs a real backend with hashed passwords before real use.
  • The recommendation text is written for demonstration. A qualified health professional should review it before anyone relies on it.
  • It has not yet been tested with real users or audited for accessibility beyond contrast and keyboard basics.
Stage 8 · Reflection

What I took from building it

Why a health project

Biology, science, health, working out and self-care are the subjects I care about most. A wellness app let me bring all of them together in one project.

The hardest decision

Balancing personalization with user safety. I wanted recommendations that fit each person, while respecting their privacy and keeping the app in its role as an educational tool that never gives potentially unsafe medical advice. That is why Vitality never diagnoses, and why a medication concern leads to general safety information and a healthcare professional.

What I would add

More detail in the diet section, with cooking tutorials and photos for each meal, and tutorials for the workout routines so they are easier to follow. This is where the next version is heading.

Designing inside a safety rule changed the product. Medication became information plus a safety flow instead of a tracker. Scope was cut on purpose: the statistics page waits for v3. Happy-path screens were the easy part. Loading, empty, error and success states took as much thought.
